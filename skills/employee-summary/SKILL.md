# 员工个人总结

## 目标
基于当前 Plan 提供的人事事实，按用户指定范围生成员工分析；未指定范围时生成完整员工画像，供前端直接渲染。

## 分析范围

- `summary_scope=full`：输出基本信息、当前职责、近一年绩效、人才盘点、个人优势、待改进项及发展建议。
- `summary_scope=partial`：只输出 Plan 指定的 `sections`，不得为了凑完整结构补充无关模块。
- `summary_scope` 和 `sections` 由 Planner 决定，Skill 不自行扩大范围。

## 规则
- 只使用 Tool 返回的数据，不补造事实。
- 只输出当前 Plan 指定的模块；用户未指定模块时才输出完整画像。
- 输出必须包含：基本信息、近期绩效、人才九宫格、个人优势、待改进项及发展建议。
- `basic_info.responsibility_summary` 不是简单复制岗位名称，而是结合员工档案中的岗位职责与最近一次已完成绩效中的 `work_content`，归纳员工当前实际负责的工作，控制在三句话以内。
- `basic_info.talent_summary` 是整合基础档案、最近一年已完成绩效、360 反馈和人才盘点结果后生成的一句话整体总结，不是单字段透传。
- `strengths` 必须综合最近一年已完成绩效的优点、360 正向反馈和人才盘点定位；每项优势都要有事实依据。
- `development.improvement_items` 和 `development.suggestions` 必须综合最近一年已完成绩效的缺点、360 改进建议和人才盘点结果；建议要区分事实问题、待验证判断和发展动作。
- 近 5 期绩效必须保留原始周期、结果和状态；`2026-H2` 若为 `target_only`，只能标记为“目标已设定，待评价”，不能参与历史绩效结论。
- 360 没有数据时明确写入数据缺口，不得推断员工没有优势或存在问题。
- 考勤只作为事实补充，不将迟到、请假或加班直接解释为能力、态度或绩效问题。
- 九宫格只引用人才盘点 Tool 返回的位置，明确横轴为绩效、纵轴为潜力。
- 不直接做淘汰、晋升、离职等最终决定；发展建议必须标记为建议或待确认。

## 处理规则

- 先按 `summary_scope` 和 `sections` 确定输出范围，再进行总结。
- `responsibility_summary` 使用员工档案和最近一次已完成绩效中的 `work_content` 归纳，控制在三句话以内。
- `talent_summary` 综合员工档案、最近一年已完成绩效、360反馈和人才盘点生成一句话整体总结。
- `recent_performance` 保留最近五期绩效的周期、结果和状态；只对已评价周期总结趋势。
- `strengths` 综合最近一年绩效优点、360正向反馈和人才盘点结果。
- `development` 综合最近一年绩效缺点、360改进建议和人才盘点结果。
- 每个重要结论都应尽量附带 `evidence_refs`，无法引用证据时降低结论强度。

## 数据边界

- 只处理当前用户有权限查看的员工和团队数据。
- 只使用本次 Plan 返回的 Tool 结果，不使用隐藏数据或历史会话补充事实。
- 工作经历、岗位、职级和项目内容只能来自档案或绩效中的 `work_content`。
- 考勤统计只能作为出勤事实，不能直接推导能力、态度、健康或人格。
- 目标期绩效不能作为已发生的绩效结果参与趋势判断。

## 数据缺失处理

- 缺少某类数据时，在对应模块写明“暂无数据”或“数据不足”，并加入 `data_gaps`。
- 没有360反馈时，不评价跨团队影响力，提示需要补充反馈。
- 没有人才盘点时，不生成九宫格位置或继任判断。
- 绩效记录少于两期时，不生成趋势结论，只展示已有记录。
- 没有项目或职责记录时，不根据岗位名称自行补充具体工作内容。

## 冲突数据处理

- 不同 Tool 对同一事实不一致时，不自行选择或平均，标记为待确认。
- 绩效结果与360反馈方向不一致时，同时呈现差异，不强行合并为单一结论。
- 当前岗位与最近一次绩效工作内容不一致时，分别呈现档案事实和绩效记录，并加入数据缺口。
- 发现周期、员工身份或权限范围不一致时，停止相关总结并请求人工确认。

## 禁止事项

- 不编造绩效分数、360反馈、人才盘点位置、职责或项目成果。
- 不根据单条记录给出员工价值判断、人格判断或心理判断。
- 不直接建议淘汰、降薪、解除劳动关系或确定晋升结果。
- 不输出薪酬、奖金、股权等敏感信息，除非有明确授权且属于当前任务范围。
- 不把“建议”“待验证信号”表述成确定事实。

## 人工确认条件

- 关键数据缺失、冲突或来源不明时，标记 `requires_human_review=true`。
- 涉及晋升、淘汰、降薪、劳动关系或重大绩效争议时，必须建议 HR / Leader 人工确认。
- 360、绩效和人才盘点结论明显冲突时，不输出单一人才结论。
- 发现当前用户无权查看相关数据时，停止生成并返回权限提示。
